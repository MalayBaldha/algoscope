# AlgoScope - Epic Breakdown

## Overview

This document provides the complete epic and story breakdown for **AlgoScope**, decomposing the functional and technical requirements from [docs/prd.md](file:///c:/Users/malay/algoscope/docs/prd.md) and architectural invariants from [docs/architecture.md](file:///c:/Users/malay/algoscope/docs/architecture.md) into actionable, test-driven user stories sized for single dev sessions.

## Requirements Inventory

### Functional Requirements

- **FR1 (Topic Hub & Navigation):** Landing page with 14 sorted topic cards displaying mastery indicators (Not Started, In Progress, Mastered), difficulty tiers, and quick navigation.
- **FR2 (Structured Topic Hubs):** Every topic provides 5 structured views: Overview/Inspiration, Interactive Demo, Dedicated Mini-App, Pattern Cheat Sheet, and Curated Problems.
- **FR3 (Frame-Driven Visualization Engine):** Deterministic execution yielding structured `Frame[]` sequences allowing play, pause, bidirectional stepping, variable inspection, speed adjustment, and timeline scrubbing.
- **FR4 (14 Dedicated Mini-Apps):** Practical applications powered by DSA (e.g. Traffic Rate-Limiter, LRU Cache, Order Book Peak Finder, Task Scheduler, Transit Route Pathfinder).
- **FR5 (Dual-Stack Learning Ownership):** Scaffolding generated by AI; owner implements Python algorithms + Pytest suites, alongside TypeScript frame reducers, canvas render adapters, and interactive client triggers.
- **FR6 (Pre/Post Assessment Grill):** Diagnostic grill session before starting a topic and post-assessment upon completion measuring Conceptual Understanding, Pattern Recognition, and Complexity Analysis accuracy (0-10 scale).
- **FR7 (Dashboard & Analytics):** Progress tracking across all 14 topics, streak recording, pre vs. post score deltas, and pattern recognition accuracy metrics.
- **FR8 (Personal Authentication):** Secure OAuth login (NextAuth.js) protecting personal instance learning history and SQLite database records.

### NonFunctional Requirements

- **NFR1 (Performance):** Local page load under 2 seconds; frame scrubber responsive with 60fps smooth playback without stuttering.
- **NFR2 (Responsiveness):** Optimized for Desktop viewport with clean adaptive layout for tablets.
- **NFR3 (Accessibility):** Semantic HTML, full keyboard navigation for playback controls, ARIA landmark regions.
- **NFR4 (Code Quality & Type Safety):** Zero lint/type errors under strict TypeScript (`tsc --noEmit`), ESLint/Prettier, and Python `ruff` / `pytest`.
- **NFR5 (Data Persistence):** Offline-first zero-configuration SQLite persistence via SQLAlchemy 2.0.
- **NFR6 (Session Independence):** All progress, state, and test configurations preserved in repo files and SQLite database.

### Additional Requirements (from Architecture)

- **ARCH-1 (Frame Schema Protocol):** Backend Pydantic models and frontend TypeScript contracts strictly adhere to `Frame(step, phase, state, pointers, highlights, explanation)` schema.
- **ARCH-2 (Pure State Machine):** Frontend `useAlgorithmPlayback` hook guarantees pure, deterministic frame navigation based on array index.
- **ARCH-3 (Dual Archetypes in Phase 2):** Phase 2 validates both ends of the visualization spectrum: Topic 1 (Arrays & Strings: Linear Canvas) and Topic 11 (Graphs: React Flow Canvas).
- **ARCH-4 (Monorepo Scaffolding):** Next.js 14 (App Router) + FastAPI (uv-managed virtualenv) monorepo structure.

### UX Design Requirements

- **UX-DR1 (Playback Control Suite):** Reusable playback bar featuring Play/Pause button, Step Back, Step Forward, Scrubber Range Slider, Speed Selector (0.5x, 1x, 2x, 5x), and Step Counter.
- **UX-DR2 (Dual Viewport Layout):** Side-by-side or stacked layout pairing the visual canvas with live code/state inspection logs.
- **UX-DR3 (Pattern Cheat Sheet Cards):** High-density, scannable reference cards with syntax snippets and time/space complexity badges.
- **UX-DR4 (Topic Card Progress Rings):** Radial or bar progress visual indicators reflecting completion percentages on the Topic Hub.

## Epic 1: Platform Foundation & Core Playback Engine (Phase 1)

**Goal:** Establish the runnable monorepo, persistent SQLite database models, NextAuth OAuth security, Topic Hub catalog, and the reusable TypeScript timeline playback engine.

### Story 1.1: Monorepo Scaffolding & Dual-Stack Environment Setup
As a **developer learning full-stack engineering**,  
I want **a configured monorepo with Next.js 14 App Router, FastAPI in Python 3.12 (uv), linters, and typechecking**,  
So that **I have a unified workspace with zero cross-environment drift**.

**Acceptance Criteria:**
- **Given** a clean clone of the repository,
- **When** `npm install` and `uv sync` are executed,
- **Then** the Next.js frontend builds cleanly via `npm run build` with Tailwind and shadcn/ui configured,
- **And** FastAPI runs via `uv run uvicorn app.main:app` responding `{"status": "ok"}` on `GET /api/health`,
- **And** strict linting (`eslint`, `ruff`) and typechecking (`tsc --noEmit`, `mypy`/`pyright`) pass without errors.

### Story 1.2: Owner-Implemented OAuth Authentication & Session Management
As the **platform owner**,  
I want **to implement NextAuth.js OAuth configuration with guided TODO stubs**,  
So that **I gain practical authentication expertise and my personal learning data is secured**.

**Acceptance Criteria:**
- **Given** an unauthenticated visitor navigating to protected routes (`/dashboard`, `/topics/...`),
- **When** the page loads,
- **Then** NextAuth middleware redirects to the sign-in screen,
- **And** when the owner completes the OAuth flow (GitHub/Google) using their implemented provider callbacks,
- **Then** the user session is created and persisted, allowing access to the protected Topic Hub and Dashboard.

### Story 1.3: SQLite Database Models & Topic Seed Scaffolding
As a **learner**,  
I want **SQLAlchemy 2.0 models for Topics, Problems, Progress, Assessments, and Streaks persisted to SQLite**,  
So that **my learning state and test results persist across sessions offline**.

**Acceptance Criteria:**
- **Given** the FastAPI backend starts with a fresh SQLite database,
- **When** database migrations or metadata initialization runs,
- **Then** tables for `topics`, `problems`, `progress`, `assessments`, and `streaks` are created,
- **And** an idempotent seed script populates all 14 DSA topics with their slugs, descriptions, difficulty orders, and key pattern tags,
- **And** `GET /api/topics` returns the 14 topics with their initial status `"not_started"`.

### Story 1.4: Frame Schema Contracts & Playback Engine State Machine (`useAlgorithmPlayback`)
As a **frontend developer**,  
I want **to implement the `useAlgorithmPlayback` hook and playback control UI adhering to the shared `Frame` schema**,  
So that **any algorithmic frame sequence can be smoothly scrubbed, stepped, and inspected**.

**Acceptance Criteria:**
- **Given** a mock sequence of 10 `Frame` objects matching `types/dsa.ts`,
- **When** the user mounts the `useAlgorithmPlayback` hook,
- **Then** clicking `Play` starts an automatic timer advancing `currentIndex` at the chosen speed (0.5x, 1x, 2x),
- **And** clicking `Pause` freezes the timeline, `Step Forward` and `Step Backward` move by 1 frame bounded within `[0, total - 1]`,
- **And** dragging the range slider scrubber jumps instantly to the target step without side-effects,
- **And** full keyboard shortcuts (Space for Play/Pause, ArrowLeft/Right for Step) control playback.

### Story 1.5: Dashboard Shell & Assessment Data API
As a **learner**,  
I want **a dashboard displaying practice streaks and pre/post assessment comparison widgets**,  
So that **I can visually track my pattern recognition rate and topic mastery over time**.

**Acceptance Criteria:**
- **Given** the user visits `/dashboard`,
- **When** `GET /api/progress` and `GET /api/assessments` are queried,
- **Then** the dashboard displays topic mastery breakdown, active daily streak, and before/after assessment radar/bar charts,
- **And** empty states are gracefully rendered with call-to-action buttons directing the user to Topic 1.

- **Then** array elements render as numbered bar/card nodes with smooth layout animations,
